# Architecture decision records

`0010` was reserved for a replace-mode restore and is now filled by the decision that there will not be one. Every number from 0001 to 0031 exists.

[ADR 0008](0008-one-check-carries-the-month.md) and [ADR 0009](0009-the-goal-chooses-its-funding-accounts.md) both change what a released screen means, so neither is a bug fix: 0008 replaces one reserve rule with four, and 0009 moves the funding relation off settings and onto the goal. Both shipped together with schema version 5 (PR #16, `100bc65`). [ADR 0011](0011-the-pay-cycle-is-a-setting.md) adds the fifth collector, makes the pay cycle editable in Settings, and carries schema version 6. [ADR 0012](0012-the-wall-remembers-its-claims.md) adds `bill_reserves` and carries schema version 7; [ADR 0013](0013-a-route-is-a-plan-not-a-movement.md) records the boundary between a plan and a ledger movement that 0012 depends on. [ADR 0014](0014-one-dialog-one-focus-model.md) is renderer-only: it replaces seven ad-hoc dialogs with one focus model and changes no stored data. [ADR 0021](0021-a-goal-carries-its-own-pace.md) makes each goal's funding behaviour its own choice and carries schema version 10. [ADR 0022](0022-the-ledger-can-live-in-a-folder-you-choose.md) lets the ledger sit in a chosen folder, stores that choice outside the database and keeps one writer at a time; it changes no table and no schema version. [ADR 0023](0023-the-phone-reads-a-backup-and-writes-only-entries.md) adds an optional installable phone view that opens a backup, reuses the desktop's money functions and exports only the entries it added; it changes no table, no schema version and no desktop write path. [ADR 0024](0024-two-copies-merge-by-time.md) supersedes its write rule: a backup now merges into either copy by last-write-wins, so an edit or a deletion made on the phone reaches the desktop in the same file, and the phone can change any entry rather than only the ones it added. [ADR 0025](0025-the-phone-writes-through-the-desktops-own-rules.md) finishes what 0024 opened: one shared validation core serves both apps, the phone's writers mirror the desktop's guards and cascades, and its deletes ask the same question first. It changes no table and no schema version. [ADR 0026](0026-a-delete-confirmation-counts-the-rows-that-leave.md) makes that question honest on the desktop too: the count of rows a delete would retire comes from the database through one expansion shared with the write itself, because the renderer only ever holds one page of the ledger, and `src/shared/deletion.ts` gives both devices the same sentence. It changes no table, no schema version and no read model. [ADR 0027](0027-one-expansion-answers-every-destructive-question.md) extends that question to the rest of the product: an account delete reuses the same expansion so it stops promising three rows and taking five, a bill delete names the set-asides that go and the entries that stay, the whole-ledger questions state their sizes from data the device already holds, and the now-unreachable `account:entry-count` channel is removed. It changes no table and no schema version. [ADR 0028](0028-both-devices-derive-a-bills-set-aside-from-its-payments.md) moves the last rule that had stayed on the computer: whether a paycheck's set-aside has been spent is derived from the ledger's payments, in `src/shared/claims.ts`, and both devices now run that walk — the desktop's repository keeps its SQL but loses its arithmetic, while the phone replays the rule at the desktop's own call sites and after every import. It changes no table and no schema version. [ADR 0029](0029-encryption-is-a-choice-on-the-disk-and-on-the-way-out.md) supersedes 0019's first line under the condition 0019 set: a ledger can now be encrypted at rest with a choice of key custody, a backup can be sealed as an envelope both devices open, and the phone's own copy can be sealed in place, **opt-in in every direction and reversible in every one** — it adds one sidecar file, swaps the SQLite driver for the cipher-capable fork, changes no table, no schema version and no IndexedDB store version, keeps plaintext as the default for everyone who never asks, and deliberately ships no PIN and no passkey. [ADR 0030](0030-self-hosting-puts-identity-at-the-edge.md) decides where a self-hosted login lives: at the edge, in whichever proxy and auth provider the operator already runs, with one tenant per container and per volume, because the app has no credential store, no session and no row-level authorization to get wrong. It changes no code: what it obliged was a compose shape and a deployment chapter, and the batch that writes them is a different batch from the one that decided. That batch has now run: `docker-compose.yml` carries the `edge` profile, `docker/edge.Caddyfile` carries the two TLS site blocks, and [DEPLOYMENT.md](../DEPLOYMENT.md#tls-a-login-and-more-than-one-person) carries the fail-closed chapter — and still no app code changed, which is the point of the decision rather than an accident of it.

## Conventions

- **Status** is one of `Proposed`, `Accepted`, `Superseded by ADR NNNN`, `Deprecated`.
- **Date** is the date the decision was accepted, in `YYYY-MM-DD`.
- An ADR describes the decision at the time it was made. Later changes belong in a new ADR, even if the old one is edited for typos.
- Implementation details live in the reference docs ([ARCHITECTURE.md](../ARCHITECTURE.md), [DATA-MODEL.md](../DATA-MODEL.md), [DEPLOYMENT.md](../DEPLOYMENT.md)); the ADR explains *why*.
